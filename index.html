01 · Executive Problem Statement & Business Value

Turning Fragmented Highway Sensors into Sub-Minute Urban Intelligence

UK drivers on the London–Birmingham corridor lose 59 to 101 hours annually to congestion (£7.5bn national impact). Legacy road loops detect slowdowns in isolation — our pipeline fuses 5 live IoT streams in real time so city operators know why traffic stopped and can dispatch emergency responders inside the 15-minute Golden Window.

5 Streams Fused per vehicle tick (Vehicle, GPS, Camera, Weather, Emergency)
3s → 60s Producer ingestion cadence with 60s S3 micro-batch compaction
2-Min SLA Spark event-time watermark handling out-of-order cellular packets
Dual BI Serverless Athena SQL + Redshift Star Schema for QuickSight

What Breaks in Traditional Municipal Traffic Systems?

Most city transport authorities operate siloed feeds: highway loop detectors measure speed, meteorological agencies log weather hourly, and emergency dispatch logs 999 incidents in a separate CAD database.

When corridor speed drops to 24.88 mph on the M6, operators waste 12–18 minutes manually correlating feeds. By streaming all 5 domains through Apache Kafka keyed by deviceId and joining them inside Spark Structured Streaming, incident context arrives already fused in S3 and QuickSight.

Stage 01: Multi-Sensor IoT Corridor Producer (`jobs/main.py`)

Simulates a connected vehicle (`Vehicle-123`, Ford Focus ST) traversing the 100-step trajectory from London (`51.5074, -0.1278`) to Birmingham (`52.4862, -1.8904`) with deterministic seed `random.seed(45)` for reproducible analytics.

Key Architectural Decision: Messages are partitioned by key=str(data['deviceId']) so all events for a vehicle land in strict chronological order on the same Kafka partition.

# jobs/main.py — Partitioning by deviceId for strict ordering def produce_data_to_kafka(producer, topic, data): producer.produce( topic, key=str(data['deviceId']), value=json.dumps(data, default=json_serializer).encode('utf-8'), on_delivery=delivery_report ) producer.flush()

04 · Core Engineering Decisions & Trade-Offs

Designed for Schema Safety, Partition Ordering & Cloud Cost Control

Three architectural decisions that keep the streaming pipeline resilient and cost-efficient in production.

SCHEMA CONTRACT DESIGN

Typed Geospatial Coordinates

Context: Passing coordinates as untyped 2-tuples (lat, lon) against numeric Spark schemas causes from_json() to coerce values to NULL and forces SQL string splitting in BI tools.

Solution: Decomposed spatial coordinates into explicit latitude: DoubleType and longitude: DoubleType fields across all five schemas for zero-loss ingestion and native QuickSight mapping.

STATEFUL STREAM DESIGN

Entity Partitioning & Silver Join

Context: Kafka guarantees message ordering only within a single partition. Random UUID keys scatter a vehicle's telemetry across partitions.

Solution: Partitioned all five Kafka topics by deviceId (Vehicle-123) and implemented a 2-minute watermarked stream-stream join producing the unified Silver corridor dataset alongside the 5 raw Bronze sinks.

CLOUD COST GOVERNANCE

S3 Small-File Compaction

Context: Unthrottled streaming micro-batches write a tiny Parquet file every 3 seconds (~6,000 files/hr), inflating S3 LIST API costs and degrading Athena scan performance.

Solution: Configured .trigger(processingTime='60 seconds') on all S3A writers, reducing S3 object creation by 20x while preserving sub-minute operational visibility.
